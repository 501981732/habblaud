# Habblaud 中文化与多 Agent 接入方案

状态：待评审，尚未实施或完成端到端验证。

## 目标与交付范围

在个人 Fork [501981732/habblaud](https://github.com/501981732/habblaud) 上实现两个方向：完整中文化，以及 Claude Code、Codex、DeepSeek Harness（DSH）、Pi 四种运行环境接入。DSH 中使用 GLM 与 DSH 使用其他模型采用同一接入方式；模型名称和运行环境分别展示。

交付包含可运行代码、中文文档与图片、本机验收记录，以及从功能分支到个人 Fork `main` 的 GitHub PR。GitHub 使用 PR，对应本次要求的 MR。保留上游来源和 MIT 声明。

本机 Codex 和已运行的 DSH + GLM 是实际联调目标。Pi 当前未安装：实现原生 extension，并在临时环境验证真实运行时加载、事件、会话及桥接；是否完成真实模型调用在验收记录中单独写明。Claude Code、Codex 原有能力必须保留。

## 已核实的现状

- 上游基线为 `d5f3718`，版本为 `0.8.0`。服务器已有 `AgentSource` / `HistoryProvider`，通过同一 Office 模型和 SSE 展示会话。
- 界面、帮助、错误提示、Canvas 气泡和横幅大量硬编码为葡萄牙语，日期格式使用 `pt-BR`。仅翻译 README 无法解决使用问题。
- README 截图和分享图片中存在葡萄牙语文字。品牌招牌只有专名 `Habblaud`，无需翻译。
- 本机 DSH 为 `0.2.0-rc.2`，会话保存为压缩的 `session.v3/v4.jsonl.zstd`，不能直接使用当前逐行 JSONL 读取器。
- DSH 原生 `sessionQuery` 可以读取并解码历史；`sessionController` 支持投递消息；`approval/request` 是带后续处理函数的实时审批链。
- Pi 提供 extension 和树形 session JSONL。`agent_end` 后可能继续重试或处理队列，最终空闲应以 `agent_settled` 等实际稳定信号为准。
- 消息、审批、账户标签和部分界面目前写有 Claude / Codex 二选一分支。新增 provider 名称本身不能完成接入。

## 方案选择

| 方案 | 优点 | 限制 | 选择 |
| --- | --- | --- | --- |
| 原生插件 / extension 接事件，复用 Office 和 SSE | 实时状态、消息、审批有明确来源；兼容 DSH 压缩历史 | 需要桥接安装和运行时版本验证 | 采用 |
| 只扫描各运行环境的会话文件 | 安装较少，适合历史补齐 | DSH 压缩格式与迁移依赖；无法可靠判断审批或双向交互 | 仅用于有明确格式的历史读取 |
| 将 DSH / Pi 伪装成 Claude / Codex | 可以复用少量现有分支 | 会话身份、工具、状态与消息语义不一致 | 不采用 |

继续沿用 Node 服务器、Vite / Canvas 客户端与现有工具链，不迁移框架。新接口采用可选字段或新增入口，缺少 `provider` 的旧记录继续按 Claude 处理。

## 中文化设计

### 语言与文案

首期语言为 `zh-CN` 和原有 `pt-BR`。首次打开默认中文，设置页可切换，选择保存在现有用户偏好中。语言切换同时更新 HTML `lang`、日期、数字、时间长度和金额格式。

共享翻译层使用有类型的消息键及参数。客户端文案直接调用翻译层；服务器生成的活动、等待原因、通知和房间效果增加可选的消息键与参数，由客户端按当前语言渲染，保留旧文本作为兼容回退。原始对话、工具参数、命令、文件路径和模型名称不参与自动翻译。

覆盖侧栏、Agent 详情、对话终端、历史、统计、时间回放、消息、审批、角色编辑、帮助、设置、连接与空状态、通知，以及无障碍标签。新增运行环境的说明和错误也须提供中文。

### Canvas 与字体

Canvas 使用同一翻译层。气泡、状态、接待区和 GitHub 横幅按实际文字宽度换行、截断或调整布局；中文使用系统可用的中文字体回退，避免依赖只含拉丁字形的像素字体。桌面与移动视口都要检查文字遮挡和缺字。

### 文档与图片

中文成为 Fork 的默认 README，保留葡萄牙语原文入口。中文安装说明覆盖四种运行环境、启停、功能差异及排错；服务器和素材说明提供中文版本。

中文 README 使用实际中文界面生成的截图和动图。分享图片中的介绍语改为中文，并更新四种运行环境的说明。图片按可见内容检查，不以文件名或提示词判断已经中文化。无文字的装饰素材和品牌专名可以保留。

## 多 Agent 架构与接口

### 运行环境身份和能力

`Provider` 增加 `dsh`、`pi`。账户、来源、历史、Agent、消息和审批都按明确 provider 分流，避免落入 Claude 默认分支。稳定身份包含 provider、账户与会话标识；工具调用按调用 ID 配对，父子关系按原生证据建立。

能力按运行环境和当前桥接状态声明：实时状态、对话、历史、消息、审批、用量。界面只显示已可用的操作。GLM 的 Token / 费用按原生事件报告；缺少额度或计费数据时显示未知，不套用 Claude 的订阅额度。

### 原生桥接的职责

桥接分为三个边界：

1. DSH Cordis 插件、Pi extension：读取原生生命周期与会话事件，提取规范化会话、活动、对话和能力；执行本运行环境的消息与审批回调。
2. Habblaud 桥接注册表和会话源：校验输入、维护连接和请求状态、去重，调用既有 Office 方法；通过统一对话来源接口供终端和历史读取。
3. 既有 HTTP / SSE 和客户端：沿用当前快照、活动和终端协议，显示 provider、可用能力及本地化文案。

桥接消息包含协议版本、provider、实例 ID、会话 ID、事件 ID / 序号、时间和事件载荷。事件覆盖会话注册 / 更新 / 结束、状态、活动、对话增量、消息确认、审批注册与结束。实例启动有新的标识，同一实例的重复事件不得重复创建角色、工具或对话。

桥接接口仅接受本机访问，沿用当前 Host、Origin、Content-Type 和本地绑定限制。桥接身份使用保存在本机、权限受限的令牌，不进入截图、日志或仓库。消息和审批还必须服从现有终端 / 消息开关。

### 对话与历史

Claude / Codex 继续使用当前文件读取器。为其他来源增加统一的对话读取边界，保持终端 SSE 的 `init` / `append` 语义；来源替换或会话切换时重新初始化，不能将新会话接在旧会话末尾。

DSH 使用 `sessionQuery.listSessions()` 和 `readSession()` 得到元数据与解码后的事件，使用原生事件跟进活跃会话。保留序号用于去重与重连补齐，不直接解压或猜测磁盘内部格式。冷历史由原生查询提供；桥接暂时断线时只能显示已取得的内容，并明确显示来源状态。

Pi 历史按 session 的 `id` / `parentId` 投影当前分支，不能将所有 JSONL 行当作当前对话。会话切换重新注册并加载对应历史。所有历史入口校验 provider、账户和会话，禁止任意路径读取。

终端历史继续遵守已有条目数、字节数及连接数上限；读取或缓存有界，持久化的本地对话缓存按私有文件处理。历史重放期间不发送即时通知或庆祝效果。

## 原生状态与双向交互

### DSH

插件注入 `sessionQuery`、`sessionController` 和 Agent 服务，订阅会话、Agent、工具和子 Agent 事件。`running` 表示当前轮仍活动，包含等待审批的时间：有实时待决请求时为 `waiting`，实际运行时为 `working`，确认结束且无待决请求时才为空闲。仅凭历史 `approval/asked` 不创建可回应的待决审批。

父子关系使用 `parentSession`、`origin` 及子 Agent 运行事件，普通会话 fork 不自动显示为正在运行的子 Agent。运行时有明确背景任务证据才显示 `shell`。

消息调用 `sessionController.prompt()`，使用唯一 `requestId`，明确 `queue` 或 `steer`。成功响应表示原生 inbox 已接收；界面和记录区分「已投递」与「模型已处理」。失败与超时可见，重复确认不会重复投递。

审批插件在实时 `approval/request` 中保留一次性回调，优先监听但不关闭原有 Web 审批。只有 Habblaud 存在可用本地页面时才接管；否则调用 `next()`。允许 / 拒绝只作用于本次请求。断线、超时或插件停止时回退原有 Web UI；原请求已取消则清理并结束，不能继续询问。晚到、重复或已取消的决定不生效。监听顺序及双 UI 并存必须实测。

### Pi

extension 处理会话开始 / 切换 / 结束，Agent 与工具事件、用户输入请求，以及稳定结束信号。工具状态按 `toolCallId` 配对；重试、压缩和队列续跑期间不得过早显示空闲。异常退出通过实例心跳与连接超时显示离线，不能无限保持工作。

消息使用 `pi.sendUserMessage()` 的原生投递方式；确认收到不等同模型完成。工具审批只实现原生 extension 可以保证的允许 / 拒绝及本地回退，不伪造 Claude 的「始终允许」或权限建议能力。

### 原有运行环境

Claude Code 的文件读取、插件消息和审批保持原有语义。Codex CLI / Desktop 的状态桥、历史和交互继续工作。修改共用分支时分别验证默认旧记录、明确 Claude 记录及 Codex 记录。

## 安装、异常与本机试用

提供可复核的安装命令和状态检查，先显示计划修改的位置，支持重复运行以及移除桥接。修改现有配置前保存备份，只加入本次桥接项，保留已有模型、认证、插件、工作目录及权限配置。

联调使用工作区内的专用测试目录和小任务。DSH 使用用户已有 GLM 配置，Codex 使用用户已有本机配置；不要求新增 API Key，不向公共 PR 写入本机凭据、真实业务对话或个人工作路径。

断线与畸形事件只影响对应来源，其他运行环境继续展示。桥接重连补齐状态；已结束的实例不能覆盖新实例。消息、审批和对话都有超时或资源上限；任何异常都不得自动批准工具。

## 执行阶段与验收

执行采用独立模块委派，主 Agent 负责共享协议、集成和最终实测。分为国际化、原生桥接、文档与图片、联调交付四个阶段；不预写逐文件实现计划。方案确认后在当前功能分支推进至验收与 PR。

| 验收项 | 必须取得的证据 |
| --- | --- |
| 中文完整性 | 实际浏览器检查设置、详情、历史、消息、审批、统计与 Canvas；中文桌面 / 移动截图；图片中的介绍语可读 |
| 语言切换 | 中文 / 葡萄牙语切换、持久化、格式更新；用户对话和命令不被改写 |
| 四种来源 | 各 provider 的身份、账户、活动、对话和历史测试；Claude / Codex 回归通过 |
| DSH + GLM 实机 | 原生插件加载；专用真实会话出现；模型名、工具执行、等待、结束及消息投递与原运行环境一致 |
| Codex 实机 | 本机 CLI / Desktop 会话识别；专用真实任务和工具状态；对话与桥接消息的直接验证 |
| Pi | 临时安装实际运行时，extension 加载与会话 / 工具事件验证；树形历史、消息 / 审批契约测试；真实模型调用单独标记 |
| 故障处理 | 重复事件、断线 / 重连、实例替换、审批取消 / 超时 / 晚到、无可用页面、并发工具和会话切换 |
| 工程交付 | 相关测试、`npm run typecheck`、`npm test`、`npm run build`、`git diff --check`；检查全部修改和新文件；PR 的 CI 状态读回 |

测试记录区分真实运行时、真实模型请求、合成事件、浏览器和 CI。任何未通过或未实测的能力都在 PR 中明确列出；不以 fixture 通过代替本机 DSH + GLM / Codex 联调。
